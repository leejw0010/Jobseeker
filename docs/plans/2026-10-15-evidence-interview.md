# 제출본 기반 대화형 면접 구현

사용자가 승인한 방향: 실제 제출한 자소서를 기준으로 질문하고, 방금 한 답변을 파고드는 꼬리질문과 근거가 보이는 피드백을 제공한다. 기존 Practice / Track 흐름을 확장하며 공개 서비스에서 관찰한 기능과 내부 구현 추정을 구분한다.

## 범위와 결정

- 제출본 우선 또는 최신본을 선택한다. 제출 표시가 없는 문항은 최신본으로 대체하며 화면에 표시한다. 면접 시작 시 버전 ID와 본문, 회사·직무·입력한 공고를 복사해 보관한다.
- 기존 테이블을 변경하지 않고 세션 맥락과 답변 코칭용 테이블을 추가한다. 로컬 SQLite는 기존 DB에서도 create_all로 업그레이드된다. Supabase에는 별도 증분 SQL을 제공한다.
- 답변 종료 뒤 사용자가 꼬리질문 또는 다음 질문을 선택한다. 원 질문당 꼬리질문은 하나이며 요청 재시도로 중복되지 않는다. 녹음 없이 텍스트로도 사용할 수 있다.
- 코칭은 명시적인 기준, 원문에 실제 존재하는 인용, 다음 연습 행동을 제공한다. 모델이 만든 인용을 검증하고 근거가 부족하면 판단을 보류한다. 진위·채용 합격 가능성·음성의 자신감은 판정하지 않는다.
- API 키가 없거나 외부 호출이 실패하면 기본 점검으로 동작하며 AI 평가로 표시하지 않는다. 기존 AI 피드백 API의 동작은 유지한다.
- 보완 항목이 있는 답변을 재연습하는 세션을 만들고 기존 기록을 유지한다.

## 작업 순서와 검증

1. 기존 pytest와 웹 빌드를 실행한다.
2. 제출 버전 우선 선택·맥락 고정·타 사용자 차단·기존 DB 업그레이드에 대한 실패 테스트를 먼저 작성하고 모델/API를 구현한다.
3. 인용 검증·텍스트별 꼬리질문·중복 방지·피드백 무효화·재연습에 대한 실패 테스트를 먼저 작성하고 코칭 API를 구현한다.
4. 연습 설정, 텍스트/녹음 답변, 선택형 꼬리질문, 원문과 기준별 코칭, 재연습 화면을 연결한다.
5. 전체 pytest, TypeScript/프로덕션 빌드, 실제 브라우저의 시작→답변→꼬리질문→회고→재연습 흐름을 검증하고 독립 코드 검토를 받는다.

## 주의해서 검증할 경계

타 사용자 지원 건/답변, 제출본 없는 문항, 면접 도중 자소서 수정, 비어 있는 전사문, 외부 서비스 실패/잘못된 JSON, 존재하지 않는 인용, 중복 클릭, 종료된 세션, 기존 데이터베이스.

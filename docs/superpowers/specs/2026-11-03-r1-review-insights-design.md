# R1. 회고 한눈에 보기(그래프·보완점·말 빠르기) — 설계

- 상태: 사용자 승인(2026-11-03, "바로 시작해"). 구현 계획: [../plans/2026-11-03-r1-review-insights.md](../plans/2026-11-03-r1-review-insights.md)
- 브랜치: `feature/review-insights`(`feature/gaze-calibration` 위).
- 범위: `web/`만. **백엔드·API·DB 스키마·새 의존성 없음.** LLM을 새로 부르지 않는다. 세션 상세 응답에 이미 있는 값으로 계산한다.
- 이어지는 단계(이 문서 범위 밖):
  - R2 질문 유형 확장과 역량 태그(스키마 변경, 별도 승인).
  - R3 세션 사이 추세와 VAD 기반 실제 말한 시간(스키마 변경, 별도 승인).

## 1. 목표와 하지 않는 것

목표
- 세션 회고 화면 맨 위에 "한눈에 보기" 카드를 둔다. 담는 것:
  - 답변별 코칭 상태 격자.
  - 답변 시간 막대(모의시험이면 제한 시간 선).
  - 말 빠르기 막대(세션 평균 선).
  - 자기 평가 막대.
  - **보완점** 목록.
- 보완점은 근거(어느 답변의 어떤 인용·수치)와 다음 연습 행동을 함께 보인다. 한 번에 5개까지 보이고 나머지는 접는다.
- LLM 없이 같은 입력이면 같은 결과가 나온다.
  - 코칭 보고서가 있으면(AI든 기본 점검이든) 그 이유·다음 행동 문구를 쓴다.
  - 없으면 미리 정한 문구를 쓴다.

하지 않는 것
- 점수·합격 가능성·성격·자신감 추정. 보완점은 연습 행동 제안일 뿐 평가가 아니다.
- 말버릇(음·어) 횟수. 전사가 말버릇을 빼고 적는 경우가 많아 셀 수 없다(A 평가 참고).
- 일반 인구 기준의 "적정 말 빠르기" 표시. 근거 자료를 확인하기 전에는 **세션 안의 내 평균** 대비만 보인다.
- 새 차트 라이브러리. SVG로 직접 그린다.

## 2. 계산 (`web/src/review/insights.ts`, 순수 함수)

| 값 | 정의 |
|---|---|
| 음절 수 | 전사문의 한글 음절(가–힣) + 영문자 + 숫자 개수. 영문·숫자를 글자당 한 음절로 보는 근사 |
| 말 빠르기(음절/분) | 음절 수 ÷ 녹음 길이 × 60. 녹음 답변·전사 있음·녹음 5초 이상일 때만 낸다. **녹음 길이에는 앞뒤 침묵이 들어 있어 실제보다 느리게 나온다**(화면에 표시. 정확한 값은 R3) |
| 세션 평균 | 말 빠르기를 잰 답변의 평균. 3개 이상일 때만 비교에 쓴다 |
| 시간 사용 | 모의시험: 녹음 길이 ÷ 제한 시간. 자유 연습은 제한 시간 선을 그리지 않는다 |
| 코칭 상태 | 답변별 기준 3개(구체성·질문 적합성·제출본 연결)의 충분/보완/판단유보. 보고서가 없으면 "점검 전" |

## 3. 보완점 규칙 (우선순위 순)

| 순위 | 규칙 | 근거 | 행동(보고서가 없을 때의 기본 문구) |
|---|---|---|---|
| 1 | 코칭 기준이 "보완"인 답변. 기준별로 묶는다 | 그 기준의 이유와 답변 인용 | 보고서의 다음 행동, 없으면 기준별 문구 |
| 2 | 모의시험에서 제한 시간을 다 씀(녹음 ≥ 제한 − 1초) | 녹음 길이·제한 시간 | 결론을 먼저 말하고 근거를 두 가지로 줄여 다시 답해 보기 |
| 3 | 모의시험에서 답변이 짧음(녹음 < 제한의 40%) | 녹음 길이·제한 시간 | 상황 → 내 행동 → 결과 순서로 한 번 더 채워 보기 |
| 4 | 전사문 50자 이상인데 본인 역할 표현(제가·저는·직접·담당·본인·맡)이 없음 | 답변 앞부분 인용 | 팀이 한 일은 그대로 두고, 그중 내가 맡은 부분과 판단을 한 문장 더하기 |
| 5 | 말 빠르기가 세션 평균보다 25% 넘게 빠르거나 느림(3개 이상 잰 경우만) | 그 답변과 평균의 음절/분 | 빠르면 문장 사이 한 박자 쉬기, 느리면 핵심 문장을 먼저 말하기 |
| 6 | 자기 평가 1~2점 | 점수 | 아쉬웠던 이유를 회고 메모에 한 줄 적고 다시 연습하기 |
| 참고 | 전사문이 없는 답변 | 개수 | 전사문을 입력하거나 음성 인식을 다시 시도하면 점검할 수 있음 |

- 같은 규칙에 걸린 답변은 한 항목으로 묶어 답변 번호를 나열한다(Q2·Q4).
- 각 항목은 해당 답변 카드로 가는 링크를 가진다.
- 기준값(40%, 25%, 3개, 50자, 1~2점)은 잠정이며 `insights.ts` 상수 한곳에 둔다.

## 4. 화면 (`web/src/components/ReviewInsights.tsx`)

**그래프**
- 막대(`BarChart`): 단일 계열 파란색(밝게 `#2a78d6`, 어둡게 `#3987e5`, 검증기 통과).
  - 4px 둥근 끝, 막대 사이 2px 간격, 막대 끝에 값.
  - 기준선(제한 시간·세션 평균)은 점선과 이름.
  - 막대마다 마우스를 올리면 값이 보인다(SVG `<title>`).
  - 그래프마다 `<details>` 표 보기.
- 코칭 상태 격자: 색은 충분 `#0ca30c`, 보완 `#fab219`, 판단유보·점검 전은 회색. 색만으로 구분하지 않게 기호와 글자를 함께 쓴다(✓ 충분, ! 보완, – 판단유보, · 점검 전).
- 값을 잴 수 없을 때는 그래프 대신 이유를 한 줄로 쓴다. 예: 녹음 답변이 없음, 전사문이 없음.

**배치**
- 회고 화면 제목 아래, 디브리프 카드 앞.
- 기존 카드(디브리프, 카메라, 답변별 카드, 다음 연습 연결)는 그대로 둔다.

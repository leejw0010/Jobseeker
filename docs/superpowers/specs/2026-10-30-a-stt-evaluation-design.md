# A. 로컬 STT 정확도 평가 — 설계

- 상태: **승인됨** (2026-10-30, 사용자 조정 반영). **결과(2026-11-01): 기본값 `base` 유지, `small` 평가는 하드웨어 한계로 미완료 — [D-20](../../decisions.md), [결과 요약](../../research/stt-eval-2026-10-30.md).** 구현 계획: [../plans/2026-10-30-a-stt-evaluation.md](../plans/2026-10-30-a-stt-evaluation.md)
- 범위: 평가 도구(`backend/evals/stt/`)와 평가 절차·판정 기준. **A 동안 기본 STT 설정(`LOCAL_STT_MODEL=base`, beam 5, VAD 켬, 프롬프트 없음)은 바꾸지 않는다.** 바꿀지는 실측 결과를 사용자와 함께 검토한 뒤 따로 결정한다(`docs/decisions.md` D-20 예정).
- 순서: D → **A** → B → C. A의 원본 전사 보존·말버릇 평가는 B(원본 vs 교정 전사)의 근거가 된다. C(선택형 영상·음성 동기 녹화·재생)는 승인된 이후 과제로 로드맵에 그대로 두며, A는 녹음 저장·전사 흐름(API, `stt_status`, 원본 삭제·보관 기한)을 건드리지 않는다.

## 1. 목표와 하지 않는 것

목표
- 같은 한국어 녹음으로 다국어 Whisper `base`와 `small`을 비교한다: CER, 전사 시간, 메모리, 빠뜨린 말, 고유명사·전문용어 인식.
- `beam_size`, VAD, 도메인 프롬프트·hotwords를 한 번에 하나씩 바꾸는 통제 변수로 시험한다.
- 공개 낭독 음성 벤치마크(P)와 자연스럽게 말한 면접 답변 검증(S)을 분리한다.
- 끝맺지 못한 문장과 말버릇(간투사·반복·말 고침)을 모델이 어떻게 다루는지 잰다.
- 누가 다시 돌려도 같은 결과가 나오는 절차와, `small`이 `base`를 대체할지 정하는 판단 근거를 미리 정한다.

하지 않는 것
- 기본값 변경, 운영 전사 경로의 동작 변경(9절의 공유 함수 추출은 동작이 같아야 하고 기존 테스트로 확인한다).
- 전사문 자동 교정·재작성. 평가는 모델이 낸 원본 그대로를 채점한다(7절). 교정은 B의 범위다.
- OpenAI STT와의 비교(S 녹음을 외부로 보내게 되므로 이번 범위 밖).
- `medium`·`large` 평가, `condition_on_previous_text`(운영값 False)·`compute_type`(int8)·온도 대체 설정 변경.
- 없는 녹음이나 정답 전사를 지어내지 않는다. S가 없으면 S 결과는 "없음"으로 적는다.
- 시스템 메모리 설정(스왑 등)을 바꾸거나 평가와 무관한 프로세스를 끄지 않는다.

## 2. 지금 상태

운영 경로(`backend/app/stt.py` `_Local.transcribe`):
- 녹음 → PyAV `decode()`(16kHz 모노 float32) → 무음 검사.
- → `model.transcribe(language="ko", task="transcribe", beam_size=LOCAL_STT_BEAM_SIZE(5), vad_filter=True, condition_on_previous_text=False)`.
- → 세그먼트 글자를 `" ".join`.
- VAD는 faster-whisper 기본값(threshold 0.5, min_silence 2000ms, speech_pad 400ms). 스레드 `min(4, CPU 수)`.

이미 잰 것(`docs/progress.md` 2026-10-30): Zeroth-Korean 낭독 20개를 이어 붙인 30·60초, `base`만. CER 0.106·0.112, 60초 전사 약 5초.
- 한계: 낭독 음성뿐이다.
- 정답이 숫자를 한글로 적어서 숫자 표기도 오류로 셌다.
- `small`·프롬프트·VAD·빠뜨린 말을 재지 않았다.
- 스크립트가 저장소에 없다.

**faster-whisper 1.2.1 프롬프트 동작 (설치본 코드로 확인, `faster_whisper/transcribe.py`)**
- `initial_prompt`는 `all_tokens`의 처음에 들어간다. 창마다 `previous_tokens = all_tokens[prompt_reset_since:]`.
- 창이 끝날 때 `not condition_on_previous_text`이면 `prompt_reset_since = len(all_tokens)`이다(1372~1383행).
- 그래서 운영 설정(False)에서는 **첫 디코딩 창(VAD로 남긴 음성 최대 30초)에만 `initial_prompt`가 들어간다.**
- `hotwords`는 `get_prompt`에 창마다 넘어간다(1205행). prefix가 없으면 모든 창 앞에 붙고, 최대 223토큰에서 잘린다(1542~1548행).
- 실제 모델에서도 같은지 1단계(6절)에서 `get_prompt` 호출을 기록해 확인하고, 결과를 `docs/progress.md`에 남긴다. 확인 전에는 이 동작을 근거로 결론을 내리지 않는다.

## 3. 평가 세트

두 세트는 섞지 않고 따로 보고한다. 판단(8절)은 S가 주 근거이고, P는 회귀 확인과 재현용이다.

### P — 공개 낭독 음성 (벤치마크)

| 이름 | 출처·라이선스 | 고르는 법 |
|---|---|---|
| P-zeroth | [Zeroth-Korean](https://huggingface.co/datasets/Bingsu/zeroth-korean) test, CC BY 4.0, 리비전 `bd173fe2` | 데이터셋 순서로 앞 100개 |
| P-fleurs | [FLEURS](https://huggingface.co/datasets/google/fleurs) `ko_kr` test, CC BY 4.0, 리비전 `70bb2e84` | 데이터셋 순서로 앞 100개 |
| P-long | P-zeroth 다음 순번(100번째부터)의 발화를 이어 붙인 긴 녹음 8개 | 60초 4개, 120초 4개 |

**받는 방법**
- Hugging Face datasets-server `rows` API(새 의존성 없음)로 받는다.
- 응답의 자산 주소에 든 리비전이 위 값과 다르면 멈춘다.
- manifest에 데이터셋·리비전·분할·순번·라이선스·출처를 적는다.

**P-long 구성**
- 이 Zeroth 미러에는 화자 id가 없어 **연속 순번 발화를 이어 붙이고, 중간에 화자가 바뀔 수 있다.**
- 발화 사이 0.5초, 앞뒤 2초, 가운데 5초 무음을 넣는다. 여러 30초 창과 무음에서 문장을 지어내는지를 함께 본다.

**인코딩**
- 모든 클립을 브라우저 MediaRecorder와 같은 WebM/Opus(48kHz 모노 32kbps)로 인코딩한다.
- 그 뒤 운영 `decode()`를 거쳐 코덱 손실까지 포함한다.

**표기 차이**
- Zeroth 정답은 숫자를 한글로("삼 월"), FLEURS 정답은 아라비아 숫자로("15미터") 적는다.
- 그래서 숫자 정규화는 정답·출력 양쪽에 똑같이 적용한다(5절 CER_num).
- P 정답은 4절 표기 없이 글자 그대로 채점한다. FLEURS 정답에는 `깁슨(Gibson)`처럼 원문 괄호가 있어 간투사 표기로 읽으면 안 된다(구현 중 발견, 2026-10-30). 괄호 속 병기는 정답에 남아 두 모델에 똑같이 불리하다.

**용어 목록**
- P의 클립별 용어 목록(고유명사·전문용어)은 정답 문장에서 뽑아 `backend/evals/stt/p_terms.json`에 둔다.
- 사람이 아닌 Claude가 정답 텍스트를 읽고 뽑은 것이므로 그렇게 표시한다.
- P의 프롬프트 실험은 이 목록을 그대로 쓰는 **상한(oracle) 조건**이다.

**한계**
- P에는 말버릇이 거의 없어 말버릇 지표는 N/A다.
- Whisper 학습 데이터에 공개 데이터 일부가 들어갔을 수 있어 P가 좋게 나와도 이 때문일 수 있다.

### S — 자연스럽게 말한 면접 답변 (검증)

- **규모:** 최소 파일럿 표본이다. 동의한 화자 3명 이상 × 답변 6개 이상, 답변 30~120초, 약 20분. 강한 통계적 주장을 하기에는 부족하므로 결과는 "이 팀의 환경에서의 파일럿 결과"로 적는다.
- **질문과 답변:** 앱 질문 은행에서 자기소개, 기술 용어가 나오는 프로젝트 경험, 행동 질문을 섞는다. 원고 없이 답한다.
- **녹음 형식:** 48kHz 모노 WAV(무손실 원본). 평가 때 P와 같은 WebM/Opus로 인코딩한다. 앱 브라우저에서 녹음한 WebM도 넣을 수 있다.
- **클립마다 메타데이터:**
  - 화자 가명, 장치, 환경, 질문 id.
  - `prompt_terms`: 앱이 답변 전에 알 수 있는 용어(질문 문구, 지원 회사·직무).
  - `terms`: 실제로 말한 고유명사·전문용어와 허용 표기.
- **보관:**
  - 녹음은 저장소 밖 `--data-dir`에만 둔다. 커밋하지 않고, OpenAI·외부로 올리지 않으며, `backend/recordings/`를 쓰지 않는다.
  - 서면 동의를 받는다(로컬 평가 전용, 외부 전송 없음, 집계치만 공개, 예시 문장은 따로 허락받은 것만).
  - 철회하면 그 화자 파일을 지우고 다시 채점한다. D-20 기록 뒤 삭제한다.
- **녹음이 아직 없을 때:** 도구가 S를 검사·채점할 수 있게 준비만 하고, 판단은 잠정으로 표시한다(8절).

## 4. 정답 전사 규칙 (S)

- 녹음을 들으며 들은 그대로 받아쓴다. 맞춤법은 표준 표기를 따르고, 띄어쓰기는 채점에서 무시한다.
- **모델 출력을 보지 않고** 쓴다.
- 다른 사람이 답변의 20% 이상을 다시 듣고 고친다. 두 사람 차이(정답 간 CER)를 보고하고, 모델 간 차이가 이보다 작으면 의미 있게 보지 않는다.

| 표기 | 뜻 | 예 |
|---|---|---|
| `(음)` | 간투사 | `(음) 저는 (어) 백엔드를` |
| `단어-` | 말을 시작하다 끊고 고침(말 고침 조각) | `프론트- 백엔드를 맡았고` |
| `//` | 끝맺지 못하고 버린 문장의 끊긴 자리 | `그래서 제가 그때 // 결과적으로는` |
| `{3월\|삼 월}` | 둘 다 맞는 표기. 채점은 더 가까운 쪽 | `{AWS\|에이더블유에스}에 올렸습니다` |

반복("그 그 프로젝트")은 들은 대로 적는다.

## 5. 지표

**채점 전 정규화**
- 정답·출력 공통으로 Unicode NFC, 공백·문장부호 제거, 영문 소문자화.
- 원본 텍스트는 그대로 따로 남긴다(7절).

**정확도 지표**

| 지표 | 정의 |
|---|---|
| **CER_content** | 출력을 간투사가 든 정답에 정렬한 뒤, 정답 간투사 구간에 걸린 편집(그 글자의 삭제·치환, 그 구간 안 삽입)만 빼고 센 편집 수 / 간투사를 뺀 정답 글자 수. 세트 합계(micro). 출력에서 낱말 목록으로 간투사를 지우지 않는다("그 프로젝트"의 지시어까지 지워지므로). 말하지 않은 간투사는 삽입 오류. 말 고침 조각·반복은 정답에 남겨 채점 |
| CER_verbatim | 간투사까지 포함한 CER |
| CER_num | 정답·출력 양쪽의 아라비아 숫자를 한자어 수 읽기로 바꾼 뒤 CER_content와 같이 계산. 간이 변환(고유어 수 "두 개"는 처리 안 함). P의 주 지표이고, 엄격 CER도 함께 적는다 |
| **빠뜨린 말** | 정렬에서 연속 5글자 이상 삭제된 정답 구간. 10분당 구간 수, 글자 비율, 구간 원문 목록 |
| **지어낸 말** | 연속 5글자 이상 삽입된 출력 구간. 10분당 수와 목록. P-long 무음 구간에 생긴 것은 따로 |
| **용어 재현율** | `terms` 각 등장이 허용 표기 중 하나로 출력에 있는 비율 |
| **거짓 용어** | 프롬프트·hotwords에 넣은 용어 중 정답에 없는데 출력에 나온 횟수. 미끼 용어 5개(말하지 않는 고정 목록)를 넣어 잰다 |
| 간투사 재현율 (S) | 정답 간투사 중 출력에 정렬되어 남은 비율 |
| 말 고침 보존율 (S) | 말 고침 조각 글자 중 출력에 남은 비율 |
| **문장 지어 붙이기 (S)** | `//` 자리 바로 뒤에 정답에 없는 글자가 2자 이상 삽입된 경우의 수와 목록 |

**자원 지표** — 모두 따로 잰다

| 지표 | 정의 |
|---|---|
| 모델 로딩(프로세스 기준 첫 로딩) | 새 프로세스에서 모델 준비까지의 시간. 디스크 캐시를 비우려면 root 권한과 시스템 설정 변경이 필요해 하지 않으므로, "OS 캐시 상태 미통제"로 적는다. 내려받은 직후 첫 로딩과 그 뒤 로딩을 따로 기록 |
| 예열 후 추론 | 5초 클립 예열 뒤 클립마다 `decode()` 시간과 `transcribe`(생성기 끝까지 소비) 시간. RTF = 전사 시간 / 녹음 길이. 60초 답변 기준 시간 = 60초·120초 P-long 클립 RTF로 계산 |
| 프로세스 최대 메모리 | 평가 하위 프로세스의 `VmHWM`과 모델 로딩 직후 `VmRSS` |
| 시스템 메모리 압박 | 실행 중 0.5초마다: `MemAvailable` 최솟값, 스왑 사용 증가량(`SwapFree` 감소), `/proc/pressure/memory`의 `some`·`full` avg10 최댓값 |

정렬은 글자 단위 레벤슈타인과 역추적으로 한다(직접 구현). 같은 정렬로 CER·빠뜨린 말·지어낸 말·간투사·문장 지어 붙이기를 계산한다.

## 6. 실험 설계

**기준 설정 B0(운영과 같음)**
- `base`, CPU, int8, 4스레드, beam 5, VAD 켬(기본 파라미터), `condition_on_previous_text=False`, `language="ko"`, 온도 기본값, 프롬프트 없음.

**설정 목록**
- 미리 고정하고 결과를 본 뒤 바꾸지 않는다.
- 모델 m ∈ {`base`, `small`}마다 아래 6개, 모두 12개.

| id | B0에서 바꾼 것 | 보려는 것 |
|---|---|---|
| `m-default` | 모델만 | **모델 비교**는 이것끼리 |
| `m-beam1` | beam 1 | 속도 대 정확도 |
| `m-vadoff` | VAD 끔 | 무음에서 지어낸 말 vs 작은 소리 누락 |
| `m-hot` | `hotwords` = 용어 + 미끼 5개 | 용어 재현율 vs 거짓 용어(모든 창) |
| `m-prompt-terms` | `initial_prompt` = 같은 용어로 만든 짧은 문장 | 같음(첫 창만) |
| `m-prompt-verbatim` | `initial_prompt` = 간투사가 든 예시 문장(용어 없음) | 간투사·말 고침 보존, 지어낸 말 |

**단계별 실행**

| 단계 | 내용 | 다음 단계로 가는 조건 |
|---|---|---|
| 0. 도구 점검 | P-zeroth 10개 × `base-default`, 같은 실행 2회 비교, 원본 JSONL·보고서 생성 | 도구가 끝까지 돌고 두 실행 결과를 비교할 수 있음 |
| 1. 프롬프트·메모리 점검 | (a) 실제 `base` 모델로 120초 클립 1개에서 `initial_prompt`·`hotwords`의 창별 `get_prompt` 기록. (b) `small`을 내려받아 10개 클립 실행, 메모리 감시 | (a)가 2절과 같은지 기록. (b)가 메모리 중단 없이 끝나면 `small` 전체 진행, 중단되면 "이 하드웨어 한계"로 기록하고 `small` 전체는 생략 |
| 2. P 전체 | 12개 설정 × P(정확도 1회). 속도는 P-long 8개로 `m-default`·`m-beam1` 4스레드 3회, `m-default` 2스레드 3회 | — |
| 3. S | 동의받은 녹음과 사람이 쓴 정답이 있을 때만. 같은 12개 설정 | — |

**메모리 감시와 안전 중단**
- 부모 프로세스가 0.5초마다 `/proc/meminfo`·`/proc/pressure/memory`·하위 프로세스 상태를 읽는다.
- 다음 중 하나가 2초 넘게 이어지면 **평가 하위 프로세스만** 끝내고(SIGTERM, 5초 뒤 SIGKILL) `aborted: memory_pressure`와 측정값을 기록한다.
  - `MemAvailable` < 200MB
  - 시작 대비 스왑 사용 증가 > 256MB
  - PSI `full` avg10 > 10
- 다른 프로세스와 시스템 설정은 건드리지 않는다.

**정확도와 반복 확인**
- 정확도는 설정마다 1회다. 0단계와 속도 반복에서 같은 클립의 출력이 같은지 확인하고, 다르면 다른 클립 수를 적는다(온도 대체 때문일 수 있음).

**환경 기록**
- CPU 모델·코어 수, RAM·스왑, OS·커널, Python과 faster-whisper·CTranslate2·PyAV 버전, 모델 저장소 리비전과 `model.bin` sha256, 스레드 수.
- git 커밋과 미커밋 여부, 시작 시 load average와 `MemAvailable`, 함께 돌던 무거운 프로세스(이름·RSS만).
- 평가가 설정한 `LOCAL_STT_*` 값만 기록하고, 앱 설정 전체나 `.env` 값은 기록하지 않는다.

**예상 소요(추정)**
- `base` 약 30분, `small` 약 2시간.
- 측정 중 다른 작업(앱 서버, 브라우저)이 돌면 속도에 영향을 주므로 환경 기록에 남긴다.

## 7. 원본 보존

`run`은 설정·클립마다 JSONL 한 줄을 쓴다:

```
{run_id, config, clip_id, set, audio_sec, decode_ms, transcribe_ms, text,
 segments:[{start, end, text, avg_logprob, no_speech_prob, compression_ratio, temperature}],
 info:{language_probability, duration_after_vad}}
```

- `text`는 운영과 같은 함수(`run_whisper`)가 만든 것이고, 그 밖의 가공은 하지 않는다.
- 원본 파일은 한 번 쓰면 고치지 않는다(같은 결과 폴더가 있으면 거부). 채점은 별도 파일로 쓴다.
- 출력을 다듬어 오류를 가리는 후처리(맞춤법 교정, LLM 재작성, 용어 치환)는 어떤 설정에도 넣지 않는다.
- 결과 폴더는 `--data-dir/results/<run_id>/`(저장소 밖)다.
- 공개 범위:
  - P 요약·예시(출처·라이선스 표기)는 `docs/research/stt-eval-<날짜>.md`에 커밋할 수 있다.
  - S는 집계치만 공개한다. 예시는 화자가 허락한 것만 넣는다.

## 8. 판단 기준

`small-default`와 `base-default`를 비교한다. 아래는 하나라도 어기면 무조건 탈락하는 관문이 아니라, **판단을 위한 목표와 위험 분류**다. 보고서는 실제 수치와 트레이드오프를 그대로 적고, 결정은 사용자와 함께 한다.

**① 치명적 품질 위험** — 확인되면 기본값 대체를 권하지 않는다
- 심각한 지어낸 말: 무음이나 말하지 않은 곳에 문장·구절(10글자 이상)이 생긴 경우가 `base`보다 많다. 특히 P-long 무음 구간과 S.
- 내용 누락: 10글자 이상 빠뜨린 구간이 `base`보다 많다.
- 문장 지어 붙이기: `//` 뒤를 그럴듯하게 완성한 경우가 `base`보다 많다.
- 미끼 용어 출력, 메모리 중단.

판단은 해당 구간을 사람이 원문과 대조해 정답 오류가 아님을 확인한 뒤에 한다.

**② 정확도 목표** (S, 없으면 P로 잠정)
- CER_content가 절대 2.0%p 이상, 상대 15% 이상 낮아지는 것을 목표로 본다.
- 함께 보고하는 것:
  - 답변 단위 짝 차이와 부트스트랩 95% 구간(1만 회, seed 0).
  - 화자별 결과, 정답 간 CER.
- 통계적 유의성은 필수 조건이 아니다(파일럿 표본). 구간이 0을 포함하면 그렇게 적는다.

**③ 작은 차이**
- 용어 재현율, 간투사 재현율, 말 고침 보존율, 5~9글자 빠뜨린 말·지어낸 말, P CER_num은 기준을 정하지 않는다.
- 두 모델의 수치와 예시를 나란히 적어 트레이드오프로 보여 준다.

**④ 자원 목표** (이 머신, 기본값 후보가 되려면)
- 4스레드: 60초 답변 전사 중앙값 ≤ 15초, 프로세스 최대 메모리 ≤ 1.5GB, 첫 로딩 ≤ 30초.
- 2스레드: 60초 답변 중앙값 ≤ 30초.
- 메모리 압박 수치는 보고만 한다.
- 메모리 중단은 "이 하드웨어에서는 불가"로 적되, 더 큰 머신에서의 가능성은 따로 적는다.

**결론 표기** — 넷 중 하나로 적는다
- **대체 근거 있음:** ① 없음, ② 목표 달성, ④ 충족.
- **대체 근거 없음:** ① 있음, 또는 ② 미달.
- **선택 사항으로만:** ①·② 괜찮지만 ④ 미달. `LOCAL_STT_MODEL=small`을 측정치와 함께 README에 적는다.
- **잠정:** S가 없어 P만으로 판단함. S 측정 전까지 기본값을 바꾸지 않는다.

어느 경우든 A에서는 기본값을 바꾸지 않는다.

**다른 변수**
- 같은 모델의 `m-default`와 비교해 수치와 트레이드오프를 보고한다.
- hotwords·프롬프트는 미끼 용어가 한 번이라도 나오거나 심각한 지어낸 말이 늘면 채택을 권하지 않는다(B의 원칙).
- 운영에서 용어를 넘기려면 API·화면 변경이 필요하므로 채택은 별도 설계로 한다.

조합(예: `small` + beam 1)은 단일 변수 결과를 본 뒤 탐색용으로만 돌린다.

## 9. 구현 구성

새 의존성은 없다. 표준 라이브러리와 이미 있는 `numpy`·`av`·`faster-whisper`·`httpx`만 쓴다.

| 파일 | 책임 |
|---|---|
| `backend/app/stt.py` | `model.transcribe(...)` 호출과 `" ".join`을 `run_whisper(model, samples, **overrides)`로 꺼낸다. 반환은 텍스트·세그먼트·info. 운영 동작은 같다 |
| `backend/evals/stt/score.py` | 정답 표기 파싱, 정규화, 숫자 읽기, 정렬, 5절 지표, 부트스트랩. 순수 함수 |
| `backend/evals/stt/configs.py` | 6절 설정 12개, 미끼 용어, 프롬프트 문장 |
| `backend/evals/stt/data.py` | P 받기·리비전 확인·이어 붙이기·인코딩, S 검사·인코딩, manifest |
| `backend/evals/stt/run.py` | 하위 프로세스 실행, 메모리 감시·중단, 시간 측정, 원본 JSONL, 환경 기록, 프롬프트 점검 |
| `backend/evals/stt/report.py` | 채점, 판단 표, 클립별 대조(정답·base·small) |
| `backend/evals/stt/p_terms.json` | P 클립별 용어(Claude가 정답에서 뽑음) |
| `backend/tests/test_stt_eval.py` | 모델 없이 검사(아래) |
| `docs/stt-eval.md` | 실행 방법, S 녹음·동의·정답 작성 안내 |
| `.gitignore` | 실수 방지 `backend/evals/stt/data/` |

테스트 범위(`backend/tests/test_stt_eval.py`):
- 표기 파싱, 정규화, 숫자 읽기, CER 손 계산 예.
- 빠뜨린 말·지어낸 말 구간, 용어·미끼, 간투사, 문장 지어 붙이기, 부트스트랩 재현성.
- 설정 목록이 6절과 같음.
- 가짜 모델로 `run`이 원본을 그대로 저장하고 덮어쓰지 않음, 메모리 중단 판정.
- `run_whisper` 기본 인자가 운영값과 같음.

실행: `cd backend && .venv/bin/python -m evals.stt.<data|run|report> --data-dir <저장소 밖 폴더> …`. pytest는 실제 모델을 부르지 않는다.

## 10. 검증

- 자동: `pytest -q`(기존 161개 + 평가 도구 테스트). 웹은 바꾸지 않지만 `npm run build`로 회귀를 확인한다.
- 실제 모델: 6절 0~2단계. 결과는 `docs/progress.md`와 `docs/research/stt-eval-2026-10-30.md`에 쓴다. S가 없으면 3단계는 "미실행(녹음 없음)"으로 적는다.

## 11. 위험

- S 정답 작성에 20분 분량 기준 2~3시간이 든다. 표본이 작아 구간이 넓다.
- 화자·마이크 다양성이 낮다.
- 이 머신의 여유 메모리가 약 1.3GB이고 스왑이 거의 차 있다. 앱 서버·브라우저가 함께 돌면 `small` 측정이 중단되거나 느려질 수 있다.
- CER_num의 숫자 변환은 근사다. 모델 비교에는 같은 방식이 적용된다.
- P 용어 목록은 사람이 검토하지 않았다.

## 12. 결정 기록 (2026-10-30 사용자 승인)

1. 공개 세트는 Zeroth-Korean + FLEURS `ko_kr`, 출처·라이선스 유지.
2. S는 화자 3명 이상 × 답변 6개, 약 20분. 동의를 받고 저장소 밖에 둔다. 최소 파일럿 표본이다.
3. 정답은 사람이 모델 출력을 보지 않고 쓴다.
4. CER은 간투사 포함·제외 둘 다 보고한다. 말버릇·말 고침·끊긴 문장·지어낸 말은 따로 평가한다.
5. 12개 설정, 한 번에 하나씩 바꾼다.
6. 운영 디코딩·텍스트 결합 경로를 그대로 쓴다.
7. 녹음·원본 출력은 저장소 밖에 둔다. 집계와 민감하지 않은 예시만 공개한다.
8. A에서 기본 모델을 바꾸지 않는다.
9. (조정) 통계적 유의성과 정확도 수치는 필수 관문이 아니라 목표다. 치명적 위험만 강하게 본다. 자원은 로딩·추론·프로세스 메모리·시스템 압박을 따로 잰다. 메모리 중단은 안전하게 멈추고 하드웨어 한계로 기록한다. 프롬프트 동작은 설치본으로 확인한다. 단계별로 실행한다. S가 없으면 판단은 잠정이다.

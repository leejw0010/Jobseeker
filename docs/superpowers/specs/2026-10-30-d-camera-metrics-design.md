# D. 카메라 지표 정의 점검 — 설계

- 상태: **승인됨** (2026-10-30, 사용자 결정 반영). 구현 계획: [../plans/2026-10-30-d-camera-metrics.md](../plans/2026-10-30-d-camera-metrics.md)
- 범위: `web/`만. 백엔드·API·DB 스키마·카메라 스트림 구조는 바꾸지 않음.
- 순서: D → A → B → C 중 첫 번째. C(영상·음성 녹화)가 나중에 같은 카메라 스트림을 쓰게 되므로, D는 스트림을 얻고 소유하는 방식(`useFaceAnalysis`의 `getUserMedia`)을 건드리지 않는다. MediaPipe 검출, 로컬 STT, 음성 녹음 흐름도 그대로 둔다.

## 1. 목표와 하지 않는 것

목표
- "얼굴 검출 비율"과 "화면을 벗어난 시간"이 같은 프레임을 서로 다르게 세서 생기는 혼동을 없앤다.
- 분석한 시간과 실제 답변 시간을 구분해 보여 준다(탭이 가려졌거나 검출이 끊긴 시간).
- "얼굴이 화면 안에 있는데 화면 이탈로 잡힌다"는 사례를 재현하고 원인을 가려낼 수 있는 방법(자동 테스트 + 실제 웹캠 절차)을 만든다.

하지 않는 것
- 임계값(`EDGE_MARGIN` 0.01, `YAW_THRESHOLD`, `PITCH_THRESHOLD`, `EPISODE_MS`, `MAX_GAP_MS`, MediaPipe 신뢰도 기본값)과 프레임 분류 규칙은 바꾸지 않는다. 바꿀지는 6절 V4 실측 결과를 보고 따로 제안·결정한다.
- 녹화 영상 재현(V3)은 이번에 하지 않는다(사용자 결정). V4 결과가 계속 맞지 않으면 나중에 추가한다.
- 시선 추적, 새 행동 지표, 서버 전송·저장 없음(D-17 유지).

## 2. 프레임 상태 (서로 배타적, 바꾸지 않음)

`faceFeatures`가 표본(초당 약 4회, `SAMPLE_MS` 250ms)마다 정확히 하나를 고른다. 위에서부터 처음 맞는 것:

| 상태 | 조건 | 뜻 |
|---|---|---|
| `none` | 검출기가 얼굴 특징점을 돌려주지 않음 | 얼굴을 **찾지 못함**. 자리를 비운 것일 수도, 조명·각도·가림·검출기 오류일 수도 있다. 사용자가 일부러 고개를 돌리거나 떠났다는 증거가 아니다 |
| `edge` | 특징점 478개 중 하나라도 x 또는 y가 [−0.01, 1.01] 밖 | 얼굴은 찾았지만 **일부가 카메라 프레임 밖** |
| `in` | 그 밖(특징점 전부가 [−0.01, 1.01] 안) | 얼굴 전체가 프레임 안 |

좌표는 MediaPipe의 정규화 좌표(원본 카메라 프레임 기준, 좌우 반전 전)다.

## 3. 혼동의 원인

확인된 것(코드)
- **C1. `edge`를 두 지표가 반대로 센다.** 지금 "얼굴 검출 비율"은 `in`+`edge`, "화면을 벗어난 시간"은 `none`+`edge`다. 답변 내내 이마 위쪽이 프레임을 넘으면 "검출 100%, 화면을 벗어난 시간 100%"가 함께 나온다.
- **C2. 미리보기와 분석 프레임이 다를 수 있다.** 미리보기는 4:3 상자에 `object-fit: cover`(좌우 반전)라서, 카메라가 4:3이 아닌 해상도를 주면 미리보기가 분석 프레임 일부를 잘라 보여 준다.
- **C3. 테스트가 이 경우를 다루지 않는다.** 테스트·가짜 검출기의 얼굴은 핵심 특징점 5개를 뺀 473개를 얼굴 가운데(0.5, 0.5)에 둔다. 이마·턱·볼 가장자리 점이 경계를 넘는 경우가 검사되지 않았다.
- **C4. 분석 시간을 답변 시간처럼 보여 준다.** 탭이 가려지면(`document.hidden`) 표본을 건너뛰고, 표본 간격은 1초(`MAX_GAP_MS`)까지만 센다. 카메라 화면이 준비되지 않은 동안(`readyState < 2`)이나 답변 중 카메라를 끄면 표본이 없다. 그런데 회고 화면에는 분석 시간만 나온다.

가설(V4 전에는 사실로 쓰지 않음)
- **H1.** 노트북 카메라 가까이 앉으면 눈·코·입은 화면 안인데 메시의 이마 위쪽(또는 턱)이 프레임을 넘어 `edge`가 된다.
- **H2.** 조명·안경·움직임 때문에 검출이 잠깐씩 끊긴다(`none`).
- **H3.** 실제 카메라가 640×480이 아닌 해상도를 준다(C2가 실제로 일어남).

## 4. 지표 정의

표본 i의 시각 tᵢ, 길이 dᵢ = clamp(tᵢ₊₁ − tᵢ, 0, `MAX_GAP_MS`). 마지막 표본은 답변 끝 시각 t_end까지: d = clamp(t_end − t, 0, `MAX_GAP_MS`)(답변 끝 시각을 모르면 기존처럼 `SAMPLE_MS`).

| 필드(`SegmentSummary`) | 정의 | 화면 문구 |
|---|---|---|
| `answerMs` | 답변 시작(`beginSegment`)부터 끝(`endSegment`)까지의 실제 시간 | 답변 시간 |
| `analyzedMs` | Σdᵢ | 분석한 시간 |
| (화면에서 계산) | max(0, `answerMs` − `analyzedMs`) | 분석하지 못한 시간 — 탭이 가려졌거나, 카메라 화면이 준비되지 않았거나, 검출이 멈췄거나, 답변 중 카메라를 끈 시간. 이 시간은 아래 어느 지표에도 넣지 않음 |
| `inMs` | Σd[`in`] | (표에는 따로 안 보임, 합 검증용) |
| `edgeMs` | Σd[`edge`] | 얼굴 일부가 프레임 밖 — 얼굴은 찾았지만 이마·턱·볼 가장자리 일부가 카메라 프레임 밖에 있던 시간 |
| `noneMs` | Σd[`none`] | 얼굴을 찾지 못한 시간 — 자리를 비웠을 수도, 조명·각도·가림 때문에 검출하지 못했을 수도 있음 |
| `noneEpisodes` | `none`이 `EPISODE_MS`(1초) 이상 이어진 구간의 수 | 1초 이상 이어진 횟수 |
| `longestNoneMs` | 가장 긴 `none` 연속 구간 | 가장 길게 이어진 시간 |
| `detectedMs` | `inMs` + `edgeMs` | 얼굴 검출 비율 = `detectedMs` / `analyzedMs` — "분석한 시간 중 얼굴을 찾은 시간(일부가 프레임 밖이었던 시간 포함)" |
| `headMs`, `turnedMs`, `downMs` | 기존과 같음(`in` 표본만) | 기존과 같음 |
| `samples` | 표본 수 | 기존과 같음 |

- 겹치지 않음: `inMs` + `edgeMs` + `noneMs` = `analyzedMs`, 검출 비율 + `noneMs`/`analyzedMs` = 100%.
- 없애는 것: `totalMs`(→ `analyzedMs`), `offMs`, `offEpisodes`, `longestOffMs`. 수치는 탭 메모리에만 있고 API·DB에 없으므로 호환성 문제는 없다. 코드·테스트·문서에 옛 이름을 남기지 않는다.
- 비율의 분모는 모두 `analyzedMs`다(분석하지 못한 시간은 모르는 시간이므로 넣지 않는다).
- 질문별 표 열: 답변 시간 | 분석한 시간 | 얼굴 검출 | 찾지 못한 시간 | 일부 프레임 밖 | 좌우 회전 | 숙임.
- 어떤 문구도 `none`을 "자리를 떠남", "시선을 돌림", "화면을 벗어남"으로 단정하지 않는다.

면접 중 실시간 문구(카메라 패널)
- `in`: "얼굴이 화면 안에 있어요" / `none`: "얼굴을 찾지 못했어요"(기존).
- `edge`: 넘은 쪽을 알린다. 예: "얼굴 위쪽이 화면 밖에 있어요", 여러 쪽이면 "얼굴 위쪽·오른쪽이 …". 위·아래는 그대로, 좌우는 **미리보기(좌우 반전) 기준**으로 바꾼다: 원본 x < −0.01 → "오른쪽", x > 1.01 → "왼쪽".
- 미리보기는 `object-fit: contain`(분석 프레임 전체를 보여 줌, 4:3이 아니면 검은 띠). 좌우 반전(`scaleX(-1)`)은 유지한다.

## 5. 진단 계측 (개발 전용, 저장·전송 없음)

- `faceFeatures`가 `edge`일 때 넘은 쪽과 크기(`overshoot: { top, bottom, left, right }`, 원본 프레임 기준, 넘지 않은 쪽은 0)를 함께 돌려준다. 실시간 문구와 진단에만 쓰고 요약에는 쓰지 않는다.
- 같은 프레임에서 핵심 부위(양 눈 바깥·안쪽 끝, 코끝, 입 양끝·위·아래 특징점)가 모두 프레임 안인지(`coreInside`)도 계산한다. 분류에는 쓰지 않는다. "`edge`이면서 `coreInside`" 프레임이 H1의 직접 증거다.
- `VITE_CAMERA_DEBUG=true`일 때만(Vite 개발 서버, `import.meta.env.DEV`와 함께 조건을 걸어 프로덕션 빌드에서 빠짐) 카메라 패널에 진단을 보인다: 현재 상태, 넘은 쪽과 크기(원본·미리보기 기준 둘 다), `coreInside`, 실제 카메라 해상도(`videoWidth`×`videoHeight`), 이번 답변 상태별 표본 수와 "`edge`이면서 `coreInside`" 수. 특징점 좌표·영상 프레임은 저장·전송하지 않는다(화면 표시만, 탭 메모리).

## 6. 검증 방법

V1. 계산 단위 테스트(`web/e2e/video-metrics.spec.ts`, 브라우저 없음, CI)
- 이마 위쪽 점만 y = −0.02이고 핵심 부위는 프레임 안인 얼굴 → `edge`, `coreInside` 참, `overshoot.top` ≈ 0.02, 나머지 0.
- 그런 프레임만 이어진 답변 → 검출 100%, `noneMs` 0, `edgeMs` = `analyzedMs`.
- `none`이 4표본마다 1번 → `noneMs` 25%, `noneEpisodes` 0.
- `in` → `edge` → `none` 6초 → `edge` → `in` → `noneMs` 6초, `noneEpisodes` 1, `edgeMs`는 앞뒤 `edge`만.
- 배타성: 섞인 순서에서 `inMs` + `edgeMs` + `noneMs` = `analyzedMs`.
- 답변 시간: 표본 사이에 5초 공백(탭 가림) → `analyzedMs` < `answerMs`, 차이 ≈ 4초(1초 상한); 마지막 표본은 답변 끝에서 잘림; 끝 시각 없으면 `SAMPLE_MS`.
- `combineSummaries`가 새 필드를 모두 더하고 `longestNoneMs`는 최댓값.
- 미리보기 기준 방향 문구: x < 0으로 넘음 → "오른쪽", y < 0 → "위쪽".

V2. 브라우저 e2e(`web/e2e/camera.spec.ts`, 가짜 검출기, CI)
- 가짜 검출기 시나리오(`localStorage "e2e-face-detector"`): 기존 기본 순서, 기존 `fail`, 새 `edge-top`(이마만 넘음, 핵심 부위 안).
- `edge-top`: 면접 중 문구 "얼굴 위쪽이 화면 밖에 있어요" → 회고 카드가 검출 100%, 찾지 못한 시간 0초, 일부 프레임 밖 시간 > 0, 답변 시간과 분석한 시간을 보여 주고 "화면을 벗어난"이라는 문구가 없다.
- 기본 시나리오의 기존 확인(켜기·끄기·다시 켜기, 수치 표시, 카메라 정리, 메모리 전용, 권한 거부, 모델 실패)은 새 문구로 고쳐 계속 통과한다.
- 미리보기 요소의 계산된 `object-fit`이 `contain`이고 `transform`이 좌우 반전인지 확인한다.

V3. 녹화 영상 재현 — **이번에는 하지 않음**(사용자 결정).

V4. 실제 웹캠 수동 절차(사용자 실행). `VITE_CAMERA_DEBUG=true npm run dev`로 띄우고 각 자세로 30초 답변한 뒤 회고 카드와 진단 값을 `docs/progress.md`에 적는다. 기존 수동 항목 3·4를 대체한다.

| # | 자세 | 확인할 것 |
|---|---|---|
| 1 | 평소 거리, 정면 | 검출 ≥ 95%, 찾지 못한 시간 ≈ 0, 일부 프레임 밖 시간, 분석한 시간 ≈ 답변 시간 |
| 2 | 카메라에 가까이(이마 위가 잘리게) | 실시간 문구 "위쪽", 진단 `coreInside` 참 → H1 판정 |
| 3 | 턱이 잘리게 | "아래쪽" |
| 4 | 몸을 기울여 미리보기의 오른쪽 가장자리로 | 문구 "오른쪽"이 미리보기와 일치(반전 확인), 반대쪽도 |
| 5 | 5초 이상 자리 비움 | 찾지 못한 시간 ≈ 5초, 1번 |

| 8 | 진단의 카메라 해상도 | 640×480이 아니면 H3, 미리보기에 검은 띠로 전체 프레임이 보이는지 |

회귀: `npm run build`, `npm run test:e2e`(AGENTS.md 스크린샷 보호 절차), `pytest -q`(백엔드는 안 바뀌지만 결과를 남김).

## 8. 결정 기록

1. "화면을 벗어난 시간"을 없애고 `none`(찾지 못함)과 `edge`(일부 프레임 밖)로 나눈다. 검출 비율은 유지하고 계산 방법을 화면에 적는다. — 사용자 승인
2. 미리보기 `object-fit: contain`, 좌우 반전과 방향 문구 일치. — 사용자 승인
3. V3 생략, V1·V2·V4로 시작. 개인 영상을 요구하지 않는다. — 사용자 결정
4. 분석한 시간과 답변 시간 구분, `none`을 의도된 이탈로 해석하지 않음, 진단은 개발 전용·저장 없음. — 사용자 추가 요구

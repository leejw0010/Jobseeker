# 설계 결정 기록

저장소 안의 자료(README, `docs/plans`, 코드 주석, 커밋)로 확인할 수 있는 결정만 적었습니다. 근거를 찾을 수 없는 "이유"는 지어내지 않고 `이유: 기록 없음`으로 둡니다. 결정을 뒤집을 때는 항목을 지우지 말고 상태를 `대체됨(D-xx)`으로 바꿉니다.

## 형식

```
### D-xx 제목
- 날짜·상태: YYYY-MM-DD · 유효 | 대체됨(D-yy)
- 결정: 무엇을 하기로 했나(한두 문장)
- 이유: 왜(확인된 것만)
- 근거: 파일 경로, 커밋, 문서 링크
- 외부 근거(있을 때만): 출처 수준과 원문 링크
```

## 출처 수준

"이유"에 논문·기업 정책·법 조문 같은 외부 사실이 들어간 경우 출처 수준을 따로 표시합니다.

| 수준 | 뜻 |
|---|---|
| 저장소 기록 | README나 `docs/` 같은 개발 문서에 그렇게 적혀 있음. 인용 원문(링크·서지·조문)은 저장소에 없고 독립적으로 확인하지 않음 |
| 외부 원문 확인 | 원문(논문·공식 정책 페이지·법령)을 직접 열어 내용과 수치를 확인했고 링크를 적어 둠 |

2026-10-28 기준으로 **외부 원문 확인** 수준에 이른 외부 근거는 없습니다. 아래 표의 주장은 모두 README에만 적혀 있고, 저장소 안에서 원문 링크나 서지를 찾지 못했습니다(`docs/plans`, `docs/research` 검색). 원문을 확인하면 링크와 확인 날짜를 적고 수준을 올립니다. 확인하지 못한 출처를 추정해서 채우지 않습니다.

### D-02 외부 서비스 없이도 앱 전체가 동작

- 근거: `backend/.env.example`, `app/config.py`, README "Supabase 연결"

### D-03 연습 전용: 실제 면접 중 보조 기능을 만들지 않음

- 근거: README "연습 전용 원칙과 P0 기능"
- 외부 근거: 저장소 기록(각 회사 정책 원문 미확인)

### D-04 녹음 개인정보 기본값
- 날짜·상태: 2026-10-15 · 유효
- 결정: 첫 녹음 전에 동의를 받고 서버가 동의 없는 업로드·재전사를 403으로 막음. 전사 후 원본을 즉시 삭제하고, 보관을 고른 녹음과 전사에 실패한 녹음은 `AUDIO_RETENTION_DAYS`(기본 30일) 뒤 자동 삭제. 동의를 철회하면 원본을 전부 삭제. 녹음은 STT에만 보내고 목소리·감정은 분석하지 않음.
- 이유: 개인정보 기본값, AI 기본법 제31조 고지 의무 대비(AI 생성 표시).
- 근거: README P0 절, `app/retention.py`, `tests/test_privacy.py`, 5c19e17·02f3876
- 외부 근거: 저장소 기록(AI 기본법 제31조 조문 미확인)

### D-05 OpenAI 키는 서버에만

- 근거: README "음성 인식·자동 전사", `app/llm.py`

### D-06 면접 시작 시 기준 자료를 복사해 고정
- 날짜·상태: 2026-10-15 · 유효
- 결정: 제출본 우선 또는 최신본을 고르게 하고, 회사·직무·자소서 버전 ID·본문·공고를 `practice_contexts`에 복사해 둠. 기존 테이블은 바꾸지 않고 새 테이블을 추가함.
- 이유: 면접 도중 자소서를 고쳐도 코칭 기준이 흔들리지 않게 하고, 기존 Supabase 데이터를 유지하려고.
- 근거: `docs/plans/2026-10-15-evidence-interview.md` "범위와 결정", `app/coaching.py:snapshot`

### D-07 AI 인용은 원문과 대조하고, 실패하면 기본 점검
- 날짜·상태: 2026-10-15 · 유효
- 결정: 모델이 낸 답변·자소서 인용을 서버가 원문과 대조함. 키가 없거나, 호출이 실패하거나, 대조에 실패하면 "기본 점검"으로 표시하고 AI 평가로 표시하지 않음. 진위, 합격 가능성, 음성의 자신감은 판정하지 않음.
- 이유: LLM 채점과 전문가 채점의 일치도가 낮음(Kendall's τ=.19–.44). 그래서 점수 대신 인용과 개선 문장을 보여 주고 "참고용"으로 표시함.
- 근거: plans 문서, README P0 "근거와 한계", `app/llm.py:verify_quote`
- 외부 근거: 저장소 기록(Kendall's τ 수치의 원 논문 미확인)

### D-08 꼬리질문은 원 질문당 1개, 다른 세션으로 새지 않음
- 날짜·상태: 2026-10-15 · 유효
- 결정: 꼬리질문은 재시도해도 하나만 생김(`answer_coaching.parent_answer_id` unique). 답변에 따라 만든 질문은 `practice_private_questions`로 표시해 질문은행에서 재사용하지 않음.
- 이유: 독립 검토에서 다른 면접으로 꼬리질문이 섞이고 중복으로 생기는 문제가 재현됨.
- 근거: plans 문서 "완료 및 검증 기록", `app/models.py`

### D-09 채점 기준은 한 곳에서 버전을 붙여 관리
- 날짜·상태: 2026-10-16 · 유효
- 결정: 세 기준(구체성·질문 적합성·제출본 연결)과 앵커를 `app/coaching.py`에 두고, 프롬프트와 `GET /practice/rubric`이 함께 씀. 새 보고서에 `RUBRIC_VERSION`(현재 `2026-10-16-star`)을 붙이고 옛 버전 보고서는 다시 채점하지 않음. 경험 질문의 구체성은 STAR로 봄.
- 이유: 화면에 보여 주는 기준과 실제 채점 기준을 일치시키려고(README에 "한 곳에 두고 함께 씀"으로 기록).
- 근거: README P0 "구체성의 STAR 앵커", `app/coaching.py`

### D-10 코칭 보고서에 채점한 전사문의 지문 저장
- 날짜·상태: 2026-10-16 · 유효
- 결정: 보고서에 전사문 SHA-256을 함께 저장하고, 전사문이 바뀐 뒤의 옛 보고서는 없는 것으로 봄.
- 이유: 점검 중에 전사문을 고친 답변의 옛 보고서가 저장되는 문제가 있었음.
- 근거: `app/models.py:transcript_hash`, README P0 디브리프 절

### D-11 id는 Postgres uuid로 바인딩하고, 형식이 틀린 id는 404
- 날짜·상태: 2026-10-16 · 유효
- 결정: `models.ID`를 SQLite에서는 String(36), Postgres에서는 UUID로 씀. uuid가 아닌 id는 DB에 보내지 않고 404로 답함(남는 경우는 `DataError` 핸들러가 처리).
- 이유: 이전에는 Supabase Postgres에서 uuid = varchar 비교 오류로 서버가 시작하지 못했음.
- 근거: README P0 "Postgres·로컬 DB", `app/main.py`, `tests/test_malformed_ids.py`, `tests/test_migration.py`

### D-12 스키마 적용: SQLite는 자동, Supabase는 수동 증분 SQL
- 날짜·상태: 2026-10-15 · 유효
- 결정: 로컬 SQLite는 서버 시작 시 빠진 테이블·컬럼을 추가하고 예전 행을 보정함. Supabase는 `schema.sql`(새 프로젝트)과 재실행해도 안전한 `migrations/*.sql`(기존 프로젝트)을 SQL Editor에서 실행함.
- 이유: 팀원이 쓰던 로컬 `jobseeker.db`를 살리고, 기존 Supabase 데이터를 지우지 않으려고.
- 근거: `app/db.py` docstring, `supabase/migrations/*.sql` 머리 주석

### D-13 디브리프는 프로세스 안 백그라운드 작업 + heartbeat
- 날짜·상태: 2026-10-16 · 유효
- 결정: 세션 종료·재생성 시 FastAPI `BackgroundTasks`로 실행함. 답변 하나를 점검할 때마다 heartbeat를 남기고, 5분 넘게 끊겼을 때만 새 작업을 시작함. 작업 중에 들어온 요청은 한 바퀴 더 돌아 반영함. 서버가 "도는 작업이 없다"고 답하면 화면은 바로 재시도 버튼을 보여 줌.
- 이유: 기록 없음(별도 워커를 두지 않은 이유는 문서에 없음). 중복 작업과 요청 겹침 문제는 02f3876에서 수정함.
- 근거: `app/debrief.py`, README P0 "세션 종료 자동 디브리프", `tests/test_debrief.py`

### D-15 확장 동기화는 URL 기준 upsert, 바뀐 문항만 새 버전
- 날짜·상태: 2026-10-13 · 유효

- 이유: 팝업 저장과 ① 제출 감지가 같은 지원 건을 가리키게 하려고.
- 근거: README "팀원과 맞물리는 부분", `extension-track/README.md`, `routers/track.py`

### D-16 경쟁 서비스는 공개 자료로만 분석하고 독창성을 주장하지 않음

### D-17 카메라 자세 분석은 브라우저 안에서만 계산하고 메모리에만 둠
- 날짜·상태: 2026-10-28 · 유효
- 결정: MediaPipe Face Landmarker를 브라우저에서 돌리고(서버 영상 모델·OpenAI Vision 미사용), 결과 수치는 탭 메모리에만 둔다. API·DB 스키마는 바꾸지 않는다. 고개 방향은 변환 행렬의 각도 대신 특징점 비율(코끝 위치 ÷ 얼굴 폭·이마–턱 길이)을 쓰고, 각 답변의 중앙값 대비 변화로 표시한다. WASM은 앱과 함께 배포하고 모델 파일만 Google 공식 주소에서 받는다.
- 이유: 사용자 요청(경량·브라우저 분석, 원본 미저장·미업로드, 결과는 우선 메모리). 행렬 각도는 축 규약을 실제 얼굴로 검증하지 못해 부호·크기를 확신할 수 없고, 비율 지표는 방향이 분명하다. 기준값(좌우 0.12, 숙임 0.06)은 대략 20°·15°를 노린 기하 추정이며 실제 웹캠으로 맞춰 보지 않았다.
- 근거: `web/src/video/metrics.ts`, `web/src/components/useFaceAnalysis.ts`, README "카메라 자세 분석", `web/e2e/camera.spec.ts`, `web/e2e/video-metrics.spec.ts`

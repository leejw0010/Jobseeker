# 실제 웹캠 시선 실험: 3회 재현 절차

G1(렌즈 응시)·G2(화면 위치)는 개발 전용 `/dev/gaze-lab`의 실험 기능이다. 면접 답변의 평가·집중도·자신감 판정에는 사용하지 않는다. 아래 절차는 사람이 직접 실행해야 하며 자동 테스트의 합성 얼굴 결과를 실제 정확도로 바꾸어 적지 않는다.

## 기존 관측과 현재 한계

`docs/progress.md`에 기록된 2026-11-03 실행 1은 뷰포트 958×910, 배율 1, 카메라 640×480이었다. G1의 처음 보는 응시 AUC는 **0.37**, 렌즈 정면·고개 돌림 toward는 모두 **0%**였다. 학습 묶음 교차 검증 AUC 0.85와 차이가 크며 실제 렌즈 응시를 구별했다는 근거가 아니다. G2의 처음 보는 네 점 오차는 중앙 **181px**, 80% **239px**, 뷰포트 너비 대비 중앙 약 19%였다. 32·120·240px 패널 모두 오차보다 작아 판정할 수 없었다. 진단 추가 전 자료이므로 실패 원인을 소급해서 확정하지 않는다.

이번 코드는 원인 진단과 무효 입력 처리를 보강한다. 새로운 실제 웹캠 실행은 하지 않았다. 임계값이나 모델을 조정하지 않았고 정확도가 개선되었다고 주장하지 않는다. 이전 실행과 새 실행은 거절·유효성 처리 버전이 다르므로 수치를 섞어 평균 내지 않는다. 새 조건으로 3회를 따로 기록한다.

## 준비

1. 로컬 개발 서버에서만 실험실을 연다. 실제 웹캠 사용은 사용자가 직접 동의하고 켠다. 평소 조명, 평소 안경, 카메라까지 약 50~60cm를 유지한다. 카메라 모델·브라우저/OS 버전·해상도·뷰포트·배율·창 위치·조명·안경 여부와 현재 Git SHA를 기록한다.
2. 창을 고정하고 확대/축소를 바꾸지 않는다. 창·배율 변화와 **카메라 해상도 변화는 별개의 무효 사유**다. 해상도가 바뀌면 과거 보정을 재사용하지 않고 처음부터 다시 한다.
3. 주기 시험을 포함한다. OS 작업 관리자도 열어 초당 4·10·15회 및 글 입력 중 CPU를 기록한다. CPU는 브라우저 내 점유율 지표와 다르다.
4. 녹화·캡처·개인 얼굴 자료 업로드 없이 진행한다. 화면의 집계 복사에는 영상·좌표·특징점·원시 표본이 포함되지 않는다. 복사한 집계에 개인 식별 정보를 덧붙이지 않는다.

## 새 보정으로 연속 3회

1. `시험 시작` 후 매 단계의 점·렌즈·회색 패널을 안내대로 본다. 안내가 없는 고개 움직임은 하지 않는다. 카메라 렌즈 단계에서는 화면 위 점을 대신 보지 않는다. 자연스러운 눈 깜빡임은 그대로 둔다.
2. 거리 단계에서는 안내에 따라 약 10cm 앞·뒤로 움직인다. 회귀 오차와 자세 변화 거절을 함께 기록하며, 많이 거절한 것을 좋은 시선 정확도로 해석하지 않는다.
3. 각 실행이 끝나면 집계 JSON과 아래 항목을 기록한다. `결과 지우기` 또는 `시험 시작`으로 새 보정을 받아 다음 실행을 한다. 같은 보정의 반복 예측을 세 번의 독립 실행으로 세지 않는다.
4. 주 실행 3회 후 선택적으로 안경·저조도 중 하나만 바꾸어 별도 실행한다. 한 번에 여러 조건을 바꾸지 않는다.
5. 창 변경과 카메라 해상도 변경을 각각 재현해 무효 사유가 구분되는지 확인한다. 무효 실행은 3회의 통계에 넣지 않는다.

## 판독 원칙

먼저 무효 입력과 눈 감김, 기준 자세 변화, 학습 분포 밖 거절, 처음→끝 드리프트를 본다. 눈 감김은 기존 기준(`OPEN_MIN_RATIO=0.5`)으로 학습에서 제외하고, 검증 결정에서는 unknown으로 남겨 분모를 줄이지 않는다. G2 네 검증점 중 하나라도 유효 표본 8개 미만이면 전체 e50/e80을 내지 않는다. 자세 변화 표시는 진단용이며 기존 거리 변화 게이트를 제외한 모델 기준을 새로 조정하지 않는다.

H1과 H2를 각각 평가한다. 학습 교차 검증과 처음 보는 응시를 분리하고, unknown을 정답으로 세지 않는다. 기존 실현 가능성 기준의 3회 중 2회 통과 여부는 후속 연구 판단의 입력일 뿐 제품 정확도 보장이 아니다. 결과가 나쁘면 임계값을 낮추어 통과시키지 않는다. 조건을 고정해 원인 가설을 하나씩 시험하고 실제 자료가 쌓일 때까지 G1/G2는 실험실에 둔다.

자동 검증은 순수 계산·가짜 검출기에서 입력 거절, 분모 보존, 메모리 보관, 화면 흐름을 확인한다. 실제 MediaPipe 모델·실제 눈·안경·조명·Safari/휴대폰 카메라 성능은 이 문서의 인간 실행으로 별도 확인한다. 기존의 간헐적인 실험실 타이밍 문제는 재현 증거가 없을 때 추측으로 수정하지 않는다.

## 음성 후보 측정과의 구분

함께 추가한 음성 요약은 기존 마이크 analyser의 10Hz 에너지 관측을 재사용한다. RMS는 검증된 발화 검출이 아니다. 전체 녹음 길이 기준의 분당 근사 음절과 에너지 발화 후보 길이 기준의 속도를 나누며, 분석 공백은 침묵이나 멈춤에 넣지 않는다. 저에너지 구간은 처음·끝을 포함한 후보이고, 전사문 추임새는 시각 없는 텍스트 후보다. 음성·영상 요약은 녹음 revision에 묶인 탭 메모리에서만 유지한다. 기존 faster-whisper의 패딩된 VAD 구간 간격은 실제 발화 시간·침묵 측정으로 사용하지 않는다.

## 2026-11-05: 실행 보존·비교 계약

실제 장치 실행은 여전히 미실행이다. `/dev/gaze-lab`은 개별 시도마다 익명 runId와 `complete|invalid|aborted|error`, 정해진 사유 코드, detector delegate·protocol/method/config/code 버전, 브라우저/OS 범주·뷰포트/DPR·알려진 카메라 크기를 남긴다. 시험 중단은 오버레이 위의 버튼으로 가능하다. 완료한 실패도 완료 분모에 남기며, 무효·중단을 성공으로 세지 않는다. raw frame·특징점·시계열·보정 계수는 내보내지 않는다. 파일을 내보내면 앱의 결과 지우기로 회수할 수 없다.

반복 참고값은 **동일 기록 조건의 fresh 보정 3회 이상**에서 화면 너비 대비 e50의 `(최대−최소)/중앙값`으로만 표시한다. 기존 `repeatSpread=0.3` 기준은 그대로 두되 이 참고값을 H2 전체 통과 인증이나 자동 기능 활성화에 쓰지 않는다. 중단/무효 실행과 누락된 e50은 반복 계산에서 제외하고 개수는 따로 보존한다. 서로 다른 조건·버전은 오프라인 비교기에서도 별도 그룹이다. 이전 무버전 `{note,runs}` 파일은 legacy로만 표시한다.

원인 가설은 아직 확정하지 않는다. 먼저 H1의 낮은 AUC가 실제 렌즈/화면 위 지시의 혼동인지, 카메라 위치나 학습→검증 자세·눈 뜬 정도·분포 밖 거절 변화인지 확인한다. H2는 실제 카메라 해상도/창/배율 변화와 타이밍·눈 특징의 잡음·거리 변화 게이트를 구분한다. 화면 점의 표시/채점 일치에 대한 합성 테스트는 사람이 점을 정확하게 보았다는 증거가 아니다. 같은 조건의 fresh 보정 3회와 진단 집계가 쌓이기 전에는 어느 가설도 원인으로 단정하거나 임계값을 바꾸지 않는다.

실행 명령, 공개 fixture 사용권과 해시, 실제 모델의 제한적 smoke 결과 및 별도 장치 파일럿은 [media-validation.md](../media-validation.md)에 있다. 팀 이식에서는 Gaze를 개발 전용으로 유지한다.

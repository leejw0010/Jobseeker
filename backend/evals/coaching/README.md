# 합성 코칭 검증 자료

`cases.json`은 여섯 질문 유형마다 두 개씩 만든 합성 질문·답변 12개다. 실제 지원자의 개인정보와 성과는 포함하지 않는다. 자동 검증은 기본 점검의 형식·인용·입력 지문만 확인한다. 현재 `human_review_status`는 모두 `not_evaluated`이며, 코칭의 교육적 유용성이나 모델 품질을 입증하지 않는다.

실행:

```bash
cd backend
.venv/bin/python -m pytest -q tests/test_practice_input_identity.py
```

HTTP 연결과 AI 응답 분기 검증은 별도 로컬 서버가 고정된 합성 응답을 반환한다. 외부 서비스에 보내지 않으며 실제 모델 출력과 구분한다.

```bash
cd web
PATH=../backend/.venv/bin:$PATH npx playwright test -c playwright.local-ai.config.ts
```

이 환경에서 Chromium 시스템 라이브러리가 필요하면 기존 프로젝트 검증 환경과 동일하게 `LD_LIBRARY_PATH=/home/user/.cache/playwright-syslibs/root/usr/lib/x86_64-linux-gnu`를 지정한다. 새 설정은 기존 e2e의 임시 DB·녹음 디렉터리를 재사용하는 방식으로 **실행마다 새 임시 데이터**를 만들고, OpenAI 주소를 loopback으로 바꾼다. 출력은 `web/test-results/local-ai/`이다. 서버 요청 본문과 인증 헤더는 로그에 쓰지 않는다.

## 추후 사람 검토 기준

각 항목을 0(충족하지 않음), 1(부분 충족), 2(충족), N/A(근거 없음)로 기록하고, 실제 인용과 판단 이유를 함께 남긴다. 합격 점수나 역량 점수로 환산하지 않는다. 서로 다른 검토자가 같은 사례를 평가하고 차이를 논의할 수 있지만 현재 그러한 검토는 실행하지 않았다.

| 항목 | 확인할 내용 |
|---|---|
| 근거 정확성 | 인용은 실제 답변·고정 자소서에 존재하고, 사실·수치·역할·기업 특성을 추가하지 않는가 |
| 질문 적합성 | 질문이 실제로 묻는 범위와 설명의 부족한 점을 연결하는가 |
| 유형 적합성 | 경험, 가정 상황, 지식, 지원 동기, 자기이해, 프로젝트 심층의 서로 다른 설명 틀을 존중하는가 |
| 다음 행동의 유용성 | 답변 전체에 하나의 실행 가능한 우선 행동을 주며 같은 조언을 기준마다 반복하지 않는가 |
| 판단의 절제 | 근거가 없을 때 판단유보하고, 대명사·성격·감정·말투·정답·합격 가능성을 추정하지 않는가 |

치명적 오류는 인용 조작, 없는 성과·숫자 추가, 가상 대응을 실제 경험으로 바꿈, 없는 기업 정보 단정이다. 이 오류가 있으면 해당 원문과 기준을 기록하고 재검토한다. 각 사례의 `review_focus`는 검토 방향이며 정답 문안이 아니다. 실제 모델 출력에 대한 검토는 아직 수행하지 않았다.
